# 数据库视图（Dodo）

## 当前架构（2026-10-23）

记录始终保存在思源原生 AV；插件只保存展示配置。配置统一存放在承载块的
`custom-dodo-views`（`schemaVersion: 1`），以真实 `viewID` 区分。下文较早的 MVP
记录中提到的分类型属性及独立块入口属于历史说明，以当前架构和源码为准。

```text
思源 AV / 原生表格视图
         ⇅
shared/av：内核请求、类型化 AV 响应、展示表格适配、keyID 字段绑定
         ⇅
数据库视图 core：日期记录、日期编解码、字段级冲突检查与写回
         ⇅
地图 / 图表 / 时间线 / 甘特 / 日历

公共 view-host 与 view-mount-lifecycle：DOM 观察、活动 iframe 身份、挂载复用及读取有效性
visual 独立模块：挂载策略、默认值/外观、渲染和交互注册、设置 Bridge
公共 view-write-coordinator：按数据库块写入互斥、成功通知与读取失效
公共配置存储：串行保存、提交后通知当前窗口的各分屏
```

- `src/shared/av/` 不依赖具体视图或插件设置，现有自定义块复用者直接引用它。
  读取默认 `createIfNotExist: false`；显式视图失效不回退到另一视图，响应视图身份不符则报错。
- `core/schedule-model.ts` 只生成真实记录。甘特分组标题及链接结构属于
  `gantt/gantt-model.ts`；日历直接消费公共日期记录，不经过甘特任务转换。
- `core/schedule-write.ts` 保留日期/进度输入检查、字段级冲突校验、双日期字段失败
  恢复和分钟精度约束；甘特旧函数名通过原路径重导出，日历直接调用公共实现。
- `core/view-host.ts` 是所有数据库视图共用的观察器与 iframe 登记处。挂载时
  `track`、卸载时 `untrack`；宿主驱动的异步渲染使用 `beginRead` 检查结果是否仍有效。
  每个分屏独立登记；原生 DOM 替换可重新认领同一 iframe。
- `core/view-mount-lifecycle.ts` 统一所有视图的生命周期；地图控件及日历 IME 宽限仍按视图策略保留，
  原生 DOM 重建可认领稳定 iframe，过期异步结果不覆盖新数据。
- `visual/visual-mount-policies.ts`、`visual/visual-initializers.ts`、
  `visual/visual-renderers.ts`、`visual/visual-interactions.ts` 维护各视图挂载、默认绑定、
  渲染和消息的独立注册。图表/甘特/日历渲染与写回各自独立，时间线导航也从模块入口抽出。
- `visual/visual-settings.ts` 用统一设置 Bridge；`core/view-write-coordinator.ts`
  实现数据库级写入互斥、写后通知及旧读取失效。
- `view-registry.ts` 集中维护内置视图的身份与入口 URL。新增视图需扩展配置类型/校验
  和相关注册表，不再为普通渲染模式增加聚合控制器分支；未引入动态第三方视图 SDK。
- 地图、时间线浏览器入口由 esbuild 打包依赖图，保持已有 URL；不再靠源码相对路径
  字符串替换来拼装这两个入口。构建监听包含公共 AV 文件。

验证入口：`npm run test:database-view-core`、`npm run test:visual`、
`npm run test:map`、`npm run test:calendar`。完整实施记录见
`docs/plans/2026-10-23-database-view-architecture.md`。

当前仍使用大页读取；超大数据集分页、跨窗口/跨设备配置广播不在本轮实现范围。

子模块：`lets-database-view`，独立于 `lets-custom-block` 加载和关闭。
地图渲染器、iframe 资源、数据库视图接管逻辑及底图配置由本模块维护。

**名称与图标：** 每个视图首次转换为地图时，如果仍使用默认表格名称和空图标，插件使用思源原生事务把名称改为「地图」，并将 Lucide `map-pinned` SVG 注册成自定义图标。原本已自定义的名称和图标不会被覆盖。首次转换记录单独保存在数据库块属性 `custom-dodo-map-view-appearance-initialized` 中，关闭地图模式也不清除：以后无论切换到表格、再切回地图，还是手动修改名称/图标，都不再自动改变。已有地图视图不会在插件加载时被强制重命名。若图标资源导入失败，使用 🗺️ 回退。

**兼容性：** 已有数据库视图配置仍使用 `custom-dodo-map-views` + 真实 `viewID`；
历史独立地图块仍可预览与设置，底图参数从旧 `custom-block` 命名空间一次性复制到新的 `database-view` 命名空间。
原有 `/plugins/siyuan-dodo/preview/map/` 链接不变。地图相关的旧斜杠菜单和旧地图块开关仍保留在「自定义块」，仅为兼容原有笔记。

# Dodo 数据库地图视图（MVP）

本功能不修改思源内核和数据库视图类型。选择一张已有的**表格视图**，在数据库顶部操作栏点击 Dodo 的「地图」按钮，即可在该视图的内容区域显示地图。数据库顶部视图栏、筛选、排序与搜索仍由思源原生功能管理；切到其他原生视图时不受影响。

## 测试步骤

1. 确保 Dodo 插件内的「地图块」功能已开启。打开包含原生「位置」字段的数据库，新建或选择一张**表格**视图。
2. 在数据库右上方原生操作栏附近找到「地图」按钮，点击后会保留真实表格视图，只隐藏表格内容，显示地图 iframe。
3. 点击地图**右上角的设置图标**选择用于坐标的**位置**列，可选映射**资源**列作为图片。标题取数据库主键。设置保存在该数据库块的 `custom-dodo-map-views` 属性内，以 `viewID` 为键。
4. 使用思源顶部的**筛选、排序、搜索**操作。iframe 使用当前 `viewID` 请求思源渲染 API 的记录，并在原生视图刷新后重读；位置缺失的记录不会显示地图点。
5. 切换到别的视图再切回来检查恢复；点击顶部「表格」按钮可取消当前视图的地图模式，回到原生表格（此前的地图字段映射也会被清除）。

## MVP 限制

- 地图右上角的「添加地点」可启动标记模式，单击地图后会向当前数据库新增独立地点记录；矫正、删除仍只在原有独立地图块中支持。点开记录使用思源原生详情。
- 保留的是数据库**顶部视图及操作栏**，不是表格内部的每列列名。
- 本功能依赖思源前端 `.av`、`.av__header` 和 `.av__scroll` 的 DOM 结构，思源升级后可能需要适配。切回表格或关闭 Dodo 后不会更改原生表格记录。
- 配置按数据库块 ID + 视图 ID 保存；镜像数据库的不同承载块需要分别启用。
- 最小版本使用一次较大的数据库视图渲染请求获取记录，不提供超大数据库的分页/增量性能优化。

## 图表和时间线视图

在数据库顶部选中一张**原生表格视图**，点击 Dodo 的「图表」或「时间线」进入对应模式。原始表格仍在，只隐藏表格内容，在同一区域显示 iframe。保留原生视图标签、筛选与排序，内容使用该视图真实 `viewID` 渲染；切回表格不会删除可视化字段配置。

- 图表使用旧图表块的 `EChartsGeneratorService`，可选择已有图表类型、分类列、分组列、聚合方式和调色板。ECharts 脚本使用思源自身 `/stage/protyle/js/echarts/echarts.min.js`。
- 时间线使用旧时间线的 `TimelineTableProvider`、`TimelineTransformerService`、TimelineJS3 iframe，可独立映射标题、开始日期、结束日期、说明、媒体等列。
- 配置按 `viewID` 保存在数据库承载块属性 `custom-dodo-database-visual-views` 中，首次命名图标的完成状态保存在 `custom-dodo-database-visual-initialized` 中。默认名称和 Lucide 图标仅在第一次启用时设置；后续可自由修改原生名称、图标。
- 地图、图表、时间线在同一个承载视图中互斥；当前 MVP 不允许直接从地图跳进图表，需要先切回原生表格。已存在的独立图表块和时间线块继续由自定义块兼容模块渲染。
- 按本地思源源码核对，`renderAttributeView` 支持 `query`。地图、图表、时间线、甘特与日历读取当前原生搜索条件，并沿用视图的持久筛选与排序；大规模数据的分页优化待后续增强。

## 统一展示入口与图表设置

数据库顶部 `.av__views` **右侧筛选按钮的左边**只保留一个 Dodo「自定义视图」按钮，点击思源原生下拉菜单可选择表格、地图、图表、时间线。选中当前模式会显示选中状态；切换时先关闭当前视图再启用目标模式，避免多个 iframe 相互叠加。

数据库图表的设置 **直接复用** 旧图表块 `ChartSettingsPanel.svelte`，包括图标式图表类型、更多类型、X/Y 轴排序与聚合、忽略零值、范围和参考线、完整颜色方案。数据库模式会隐藏独立图表块特有的来源块 ID 和折叠开关，数据固定从当前 `viewID` 获取，自动保存完整配置到 `custom-dodo-database-visual-views`；旧独立图表块的设置与保存路径不变。

### 图表字段的精简规则（2026-10-18）

- 数据库图表 **Y 轴只可选数字（`number`）或多选（`mSelect`）列**，不再提供「记录数量」或其他字段类型的可选入口。
- 数字列可选择「值 / 总和 / 平均数 / 最小值 / 最大值 / 中位数 / 不重复的值」；多选列固定为「计数」（该列非空的记录条数），没有第二层统计选择。
- 新建数据库图表默认绑定第一列数字；没有数字时尝试第一列多选。若两种列都不存在，提示先增加支持的字段，不自动选择其他字段。
- X 轴仍允许单选字段：思源单选值通常由 `mSelect[0].content` 返回，需按实际选项分别归类；也兼容旧 `select.content`。不对普通文本执行逗号拆分。
- 为兼容历史笔记，**已保存的其他 Y 指标不会被批量删除或修改**；若想改用新规则，可手动重新选择数字或多选。旧独立图表块保持既有功能。

### 多数字列 Y 轴（2026-10-18）

数据库图表默认仍为**一个 Y 列**。当所选主 Y 列为数字时，柱状图、条形图、折线图、面积图（含堆叠与平滑变体）显示「添加数值列」，可以增加第二列、第三列等。新增行沿用 X/Y 的思源原生下拉组件，可逐行更换或删除。每条数值系列使用原始列名，全部共享当前的「统计方式」；多系列按 X 轴类别分别统计，并通过图例区分。每个附加字段保存为 `y.columns: string[]`（稳定 keyID），主字段仍为旧格式 `y.column`，不批量迁移已保存的单列配置。

同一 Y 字段不得重复使用，不允许选 X 字段或非数字列。多指标时不使用「分组方式」，添加第一条附加 Y 时会清空分组设置；删回单列后分组设置重新可选。多选 Y 固定计数且不支持增加第二指标；饼图、漏斗图和散点图仍只显示主 Y 列，切回多系列图表时会恢复原有附加列设置。

### 公共二级菜单（Svelte 4）

图表设置的主 Y 轴及附加数值列统一使用 `src/components/ui/NestedSelectMenu.svelte`（Bits UI 0.22 的公共封装）：数字列右侧展开「值 / 总和 / 平均数 / 最小值 / 最大值 / 中位数 / 不重复的值」二级菜单，多选列直接选择并固定计数。原来单独显示的「统计方式」下拉项已移除；**多数字列仍共用同一个聚合方式**。X 轴和其他设置仍采用思源原生 `b3-select`，不修改图表的数据保存格式或数据库视图绑定。

### 时间线 iframe 加载修复（2026-10-18）

- 独立 iframe 的 `services/field-mapping.ts` 使用 `../../core/av-field-binding`，必须在 `vite.config.ts` 输出资源阶段将编译后的导入改写为 `../av-field-binding.js`。错误路径会使 **ES 模块在执行 `main.js` 前加载失败**，页面一直停在「正在加载时间线预览...」。
- `services/converter-service.ts` 属于主插件侧逻辑，依赖插件 settings/plugin/api，不在 iframe 内执行，禁止继续打入 iframe 的独立静态模块资源；历史 `dist` 因 `emptyOutDir: false` 可能留有不再被入口引用的旧文件。
- `iframe/index.html` 内的独立非模块脚本负责 15 秒启动超时提示和手动「重试加载」。配置错误则由 `iframe/main.ts` 捕获并直接显示。两者均不改变源数据库内容。
- 运行 `npm run build && npm run test:timeline-preview` 对 **从 iframe/main.js 可达的真实模块依赖链** 做检查，不因历史残留的未引用构建文件误报。已通过隔离 Chrome + 模拟空配置的实际浏览器启动验收（加载提示消失、有明确错误、无资源和脚本异常）。

### 时间线字段映射类型与 TimelineJS3 字段补齐（2026-10-18）

本地 `timeline3 参考源码目录` 的核心 `timeline.js`、`timeline.css` 与内置 `timeline3` 文件哈希一致。事件 `start_date`、`end_date`、`text.headline/text`、`group`、`display_date`、`media`、`background.color` 已实现；新补充 **`media.caption`（媒体说明）、自动生成 `media.thumb/thumbnail`（使用原媒体图片）、`background.url`（背景图片）**；原来单独的「媒体来源」「媒体缩略图」字段映射已精简移除。事件 `unique_id` 继续自动生成，不要求额外绑定字段。

| 映射字段 | 思源数据库允许的列类型 | 必填 |
| --- | --- | --- |
| 标题 | 主键 `block`、文本 `text` | * |
| 开始时间 | 日期 `date` | * |
| 结束时间 | 日期 `date`（包含 `:end` 虚拟结束列） | 否 |
| 说明 | 主键、文本、模板 | 否 |
| 分组 | 单选、多选、文本 | 否 |
| 显示日期 | 文本 | 否 |
| 媒体、背景图片 | 附件、网址、文本 | 否 |
| 媒体说明 | 文本 | 否 |
| 背景颜色 | 文本、单选 | 否 |

数据库时间线及独立时间线块设置均按字段用途筛选可选列，必填标签显示红色 `*`；映射存 `keyID` 而非列名。`resolveTimelineColumns` 在数据库模式校验字段类型，并仅为标题、开始时间自动选择正确类型的字段。数据库视图保存前检查必填映射，缺少时显示明确错误。普通 Markdown 表格没有列类型元数据，保持原本按表头映射的兼容能力。失效/错类型旧映射仅提示修复，不自动猜测并绑定同名新列。


### 数据库时间线：自动标题与共享外观设置（2026-10-18）

`renderAttributeView` 在某些版本不返回顶层数据库 `name`，原先仅读取该字段会使开场标题始终退回「时间线」。现使用 `/api/av/getAttributeView` 的 **`data.av.name`** 作为权威数据库名称；不可用时再退回 `renderAttributeView.name`，均缺失时才显示「时间线」。数据库时间线一律使用当前数据库名，忽略以前保存的 `timeline.title`；数据库改名后刷新即生效。独立 Markdown 时间线仍支持其手动标题。标题进入 TimelineJS3 前经过 HTML 转义。

数据库视图现在复用原来的 Svelte 4 `TimelineSettingsPanel`，不再另行维护 DOM 拼装的纵向字段设置：在「字段映射」中左侧字段名、右侧下拉框，按类型过滤且标题/开始日期带红色 `*`；「外观」包含只读的数据库开场标题、**预览高度（320–1200px）**、**时间线占比（0–100%）**、**开始位置（开头/结尾）**。数据库时间线和图表一致，修改字段映射或外观后 **300ms 防抖自动保存** 到对应原生视图 `viewID` 的 `VISUAL_ATTR` 配置；保存成功后 iframe 高度同步变化并刷新 TimelineJS3。无「保存设置」按钮；状态显示等待自动保存、保存中或保存错误。快速连续修改由串行队列按先后写入最新配置，关闭设置窗口时立即提交尚未保存的配置；失败会提示并保留修改，允许再次修改重试。「刷新时间线」保留，刷新前先等待待保存配置落盘。继续按 keyID 绑定，不修改数据和其他视图设置。

### 数据库时间线标题点击打开条目（2026-10-18）

时间线事件的**幻灯片正文标题**支持单击以及键盘聚焦后 Enter/空格打开对应思源数据库记录，复用地图视图的 `openMapItem`：如果该行主键绑定文档块，则通过原生 `openTab(doc)` 打开实际文档；否则使用 `itemID`、主键 `valueID`、`avID`、数据库块 ID 打开原生 `siyuan-database-row` 独立条目。开场页数据库标题保持只读、不跳转；下方时间轴标记仍负责切换幻灯片，不抢占点击。

字段由 `adaptAttributeViewRender` 暴露的 `rowBlockIds/rowBoundBlockIds/rowValueIds` 经 `TimelineTableProvider` 逐行传入转换器；转换事件保留 `unique_id` 对应的 `record` 元数据，iframe 通过 `.tl-slide[id]` 精确定位记录，避免按日期排序、筛除无日期事件、同名事件或分组后错误跳转。缺少有效条目身份时不添加点击行为。iframe 使用 `postMessage` 通知主插件，主插件先检查同源、消息源仍属于当前选中的时间线视图，并校验 avID/数据库块 ID 一致，再复用地图导航函数。

`npm run test:timeline-navigation` 覆盖独立与绑定文档、日期排序与缺日期跳过、缺失 ID、Markdown 表格不跳转、消息源校验；隔离 Chrome 用正式 `dist/preview/timeline/iframe` + 模拟数据库渲染数据实测标题能点击、消息包含正确 itemID/valueID/avID，无浏览器脚本异常。

### 字段映射公共 UI + 思源原生类型图标（2026-10-18）

数据库时间线和独立时间线统一改用 `src/components/ui/FieldMapping.svelte` + `FieldSelect.svelte`。设置仍保留左字段名、右下拉框，红色必填星号、AV 类型限制、keyID 和失效绑定提示。下拉选项及当前选中值显示思源 SVG 列类型图标（如主键 `iconKey`、日期 `iconCalendar`、多选 `iconList`），不是独立的图标包。原来的时间线 `TimelineSettingsPanel.svelte` 不再自己维护字段映射 `<select>` 和类型筛选逻辑。其他模块今后可以按共享接口复用，而无需引入 React 或 Svelte 5。

### 地图与图表字段映射统一图标布局（2026-10-18）

### 首次自动绑定，后续仅通过 keyID 读取（2026-10-18）

数据库时间线、图表、地图均在初始创建/首次加载的后台流程将选出的真实列 keyID 保存到原有视图属性。时间线每个字段取接受类型的第一个真实列（标题优先 `block` 主键），图表 X 优先主键/类别、Y 首选第一个数字列，没有则首个多选列；地图坐标/图片各取首个位置/附件列。初始化后不会再按名称、列位置或类型重新选择，失效 ID 原样保留并要求用户手动重绑。可选字段空值表示明确「不使用」，不随新增字段自动开启。界面永不显示「自动」，优先显示 ID 对应最新列名和思源原生图标。修改已绑定列名或重排不更改配置 keyID，旧版列名配置只在能唯一解析时迁移一次。

### 数据库时间线同一日期列的起止时间（2026-10-18）

移除「媒体来源」「媒体缩略图」两项字段映射，保留「媒体」和「媒体说明」。时间线转换不再读取旧配置中的 `mediaCredit` / `mediaThumbnail`；这些旧 keyID 可以保留在历史配置中，但不会再影响渲染，下次通过数据库设置保存时由现有字段白名单自然清理。媒体类型是图片时，仍自动以媒体本身的 URL 作为 `thumb` / `thumbnail`，因此无需再维护独立缩略图列。对其他视图或数据库源列无影响。


### Agent 新建 AI 自定义视图（防覆盖）

`dodo-database.custom.current` 定位用户正在查看的数据库视图；
`dodo-database.custom.create` 对**非自定义视图**先创建一张新的思源原生表格视图，
再仅为新 `viewId` 生成 HTML 应用和自定义配置，不覆盖原表格、地图、图表等视图。
创建结果返回 `createdViewId`、`sourceViewId`、`appId`、`html`、`version`；
即使思源尚未切换到新标签，Agent 也可以用 `appId` 保存新 HTML。
如果当前视图本来就是 Dodo 自定义视图，按原 `appId` 修改，不重复创建。
底层通过思源原生 `addAttrViewView` 事务新增可见视图标签，新标签可能被思源自动选中，
但旧视图类型及插件配置保持原样。


### 地图：为已有数据库条目添加位置

地图视图右上角「添加地点」现在提供两个原生菜单操作：

- **新建地点**：保留原逻辑，地图点选后创建新的独立数据库条目。
- **为已有条目添加位置**：打开右侧未定位条目列表（支持标题搜索）。
  选择条目后进入地图选点模式，显示临时位置标记和坐标确认浮层。
  点击「确认位置」才会写入该条目的原生 `location` 列；
  「重新选点」可修改预览位置，按 Esc 或「取消」不会写入。

列表来自当前原生数据库视图，按实际 `itemID` 写回，**不会新增行或覆盖原始标题与文档关联**。
仅位置列真正为空的条目可以选择；非空无效坐标需在源数据库修正。
写入前重新读取并核验数据库、视图、条目、位置 keyID 和原生单元格，
避免数据变化后写入错误位置。支持 Leaflet（OSM/高德瓦片）、高德 API2、Google 底图，
地图选点与地点搜索均可在定位模式下提供候选坐标。


### 全视图统一原生数据标准

所有数据库视图共用 `src/shared/av/av-normalized.ts` 的原生 AV 强类型模型：
`fields[id,name,type]`、`records[itemId,blockId,valueId,cells]`、
单元格 `value / display / tableDisplay / details` 和 `date[start,end,allDay,startDisplay,endDisplay]`。

- 地图、图表与数据库时间线仍通过 `av-data-adapter.ts` 获取兼容的表格数据；
  表格适配器现在由强类型记录转换，不再重复推断日期或条目 ID。
- 甘特图、日历沿用独立的日程模型和交互，但日期、任务标题、原始记录身份
  来自同一个强类型模型；日期写入仍走 `core/date-codec.ts` 和原生 AV 接口。
- AI 自定义 HTML 视图 SDK 继续提供 `getSchema/listRecords/updateCell` 等现有方法，
  其 `values/displayValues/valueDetails` 使用相同的单元格标准，
  保留已有 HTML 应用的数据结构和授权策略。
- 日期字段 `content/content2` 原始时间戳不变；`isNotTime` 区分纯日期和带时间；
  优先读取思源原生 `formattedContent` 的日历日期，
  没有显示串时使用本地日历字段。**禁止通过 `toISOString()`
  或直接 `new Date('YYYY-MM-DD')` 再取本地日期作为数据库日历日。**
- 字段绑定统一以原生 `keyID` 为准，避免重名、重排、改名造成误绑定；
  `itemId` 始终是 AV 条目 ID，`blockId` 是绑定文档 ID，`valueId` 是主键单元格 ID。
- 渲染引擎和交互状态仍由各视图独立管理，统一标准不强制视图使用自定义 HTML SDK 的 RPC。

### 时间线条目链接：保留原视图与当前事件

时间线标题点击或键盘回车打开数据库条目时，在思源右侧分屏打开绑定文档／独立条目，
**不会把左侧时间线所在编辑页替换为条目**。
时间线 iframe 采用 AV 同级的稳定挂载容器，避免数据库块被宿主重建时销毁。
当前浏览的事件 `unique_id` 按数据库 `blockId + viewId` 保存在当前会话，
数据刷新、主题切换或 iframe 重新建立时恢复到该事件，而不是跳回首页。
事件已被删除或筛选掉时，安全回退到视图默认起点，不跨不同数据库视图串用进度。
